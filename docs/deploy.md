# 上线手册

把后端部署到一台服务器上，配好 HTTPS，让小程序能连上。

对应计划书第 6 节的**第三阶段**。本文档假设你有一台全新的 Linux 服务器和一个域名，
除此之外不需要任何前置知识。全程大概 30 分钟。

---

## 0. 先想清楚：为什么非得买服务器和域名

微信小程序**只允许请求 HTTPS 域名**，不允许请求 IP 地址，也不允许 HTTP。
这是微信的硬规定，绕不过去。所以上线必须有：

- 一台有公网 IP 的服务器（轻量云最低配就够，100-300 元/年）
- 一个域名（几十元/年），解析到这台服务器
- 一张 HTTPS 证书（免费，Caddy 自动申请，不用管）

计划书第 4 节的成本表说的就是这笔钱。**在真有客户用之前不用花**，
本地用 `devLogin` 把流程跑通完全免费。

---

## 1. 准备服务器

买一台 Linux 服务器（Ubuntu 22.04 或更新），配置最低档即可（1核 1G 足够跑几百个用户）。

买完之后在云厂商的**防火墙/安全组**里放行两个端口：

| 端口 | 用途 |
|---|---|
| 80 | Caddy 申请证书时要用（Let's Encrypt 走这个端口验证） |
| 443 | HTTPS，小程序实际请求走这里 |

> 8811 是后端端口，**不要**对外放行。它只在容器内网被 Caddy 访问。

SSH 登录服务器，装 Docker：

```bash
curl -fsSL https://get.docker.com | sh
```

## 2. 域名解析

去域名注册商的控制台加一条 A 记录：

| 类型 | 主机记录 | 记录值 |
|---|---|---|
| A | `api` | 你服务器的公网 IP |

这样 `api.你的域名.com` 就指向服务器了。等几分钟生效，验证一下：

```bash
ping api.你的域名.com     # 显示的 IP 应该就是你服务器的 IP
```

> **国内服务器需要备案**，没备案的域名在国内服务器上走不通 80/443。
> 备案要 10-20 天，建议买服务器的时候就一起办。
> 用香港/海外服务器可以免备案，但国内访问会慢一些。

## 3. 拉代码、填配置

```bash
git clone <你的仓库地址> suda-pro
cd suda-pro/deploy
cp .env.example .env
```

生成两个密钥（**分别执行两次，用两个不同的值**）：

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

编辑 `.env`，把下面几项填上：

| 变量 | 填什么 | 填错的后果 |
|---|---|---|
| `DOMAIN` | 第 2 步那个域名，如 `api.你的域名.com` | 证书申请不下来，小程序连不上 |
| `JWT_SECRET` | 刚生成的第一个随机串 | 泄露 = 任何人可伪造任意用户登录 |
| `STAFF_KEY` | 刚生成的第二个随机串 | 泄露 = 别人能乱改订单状态 |
| `WX_APPID` / `WX_SECRET` | 微信公众平台 → 开发管理 → 开发设置 | 不填就起不来（见第 5 节） |
| `PHOTO_SERVICE_FEE` | 入库拍照服务费（人民币元/包裹），默认 `2.50` | 收错钱 |
| `ADMIN_ALLOWED_IPS` | 你自己的固定公网 IP；没有就填 `0.0.0.0/0 ::/0` | 填窄了自己打不开后台 |

> `.env` 里全是密钥，**已经在 `.gitignore` 里了，不要提交到 git**。

## 4. 启动

```bash
docker compose up -d --build
```

第一次启动时 Caddy 会自动去申请 HTTPS 证书，大概十几秒。看一眼日志确认：

```bash
docker compose logs -f
```

然后验证服务活着：

```bash
curl https://api.你的域名.com/health
# 期望输出：{"ok":true}
```

看到 `{"ok":true}` 就成了。

## 5. 如果启动失败

大概率是配置自检拦住了。日志里会直接写清楚哪一项不合格、为什么、怎么改，例如：

```
生产环境配置自检没通过，服务拒绝启动。请修正以下问题：
  1. JWT_SECRET 还是默认值 'dev-secret-change-me'。这个值是公开写在代码里的，
     任何人都能用它签出任意用户的登录 token，等于所有账号不设防。
     生成一个：python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

**这是故意设计成起不来的。** 带着默认密钥跑起来比起不来危险得多——它不会报错，
你会以为一切正常，直到有人用公开的默认密钥登进任意账号。

自检检查三项（只在 `APP_ENV=production` 时生效，本地开发不受影响）：

1. `JWT_SECRET` 不能是默认值、不能短于 24 位
2. `STAFF_KEY` 必须设置、不能短于 24 位
3. `WX_APPID` / `WX_SECRET` 必须配齐 —— 因为这两个只要有一个空着，
   本地联调用的 `devLogin` 就还是启用状态，而它填个用户名就能登录，等于线上留了个后门

改完 `.env` 重启即可：

```bash
docker compose up -d
```

## 6. 小程序端配置

**A. 在微信公众平台登记服务器域名**

开发管理 → 开发设置 → 服务器域名 → `request 合法域名` 里加上
`https://api.你的域名.com`。不加这一条，正式版小程序发不出请求。

**B. 改小程序里的后端地址**

编辑 `miniprogram/utils/config.js`：

```js
const BASE_URL = 'https://api.你的域名.com';
```

**C. 上传代码**

微信开发者工具 → 上传 → 在公众平台提交审核。

> 跨境物流类目可能要额外资质，第一次大概率被打回，按审核意见改了再交。
> 这是计划书第 6 节第三阶段里预期会发生的事，不用慌。

## 7. 仓库后台

浏览器打开 `https://api.你的域名.com/admin/`，填入 `.env` 里的 `STAFF_KEY` 保存，
就能操作"待入库包裹 / 待发货订单 / 运输中订单"三个 tab。

这个页面有两层保护：来源 IP 白名单（`ADMIN_ALLOWED_IPS`）+ 共享密钥（`STAFF_KEY`）。
目前还没有员工账号体系，所以**这个密钥等同于仓库的全部权限**，只发给真正要操作的人。

四个 tab 对应仓库的四件事：

| Tab | 干什么 |
|---|---|
| 待入库包裹 | 包裹到仓后**称重**入库（重量必填，运费按它算）、补传照片 |
| 待拍照 | 客户付费申请了入库拍照、还没拍的包裹。拍完才计费 |
| 待发货订单 | 打包、拍留底照、填国际转运单号标记发货 |
| 运输中订单 | 给在途订单追加物流轨迹节点 |

照片直接在页面上选文件上传，手机浏览器打开这个页面可以直接调摄像头拍。

## 8. 日常运维

```bash
# 看日志
docker compose logs -f api

# 更新代码后重新部署
git pull && docker compose up -d --build

# 备份数据库（订单和用户数据都在里面，建议做个每日定时任务）
docker compose cp api:/data/suda.db ./backup-$(date +%F).db

# 备份包裹照片（打包留底照是出纠纷时的证据，别只备份数据库）
docker compose cp api:/data/uploads ./photos-backup-$(date +%F)
```

> 数据库和包裹照片都在名为 `api-data` 的 docker volume 里（容器内的 `/data`）。
> `docker compose down` 不会删它，但 `docker compose down -v` **会连数据一起删掉**，
> 别手滑。

> 照片会越攒越多，留意磁盘。看一眼：
> `docker compose exec api du -sh /data/uploads`
>
> 上传时已经压过（长边 2000px，一张约 300-600KB），500 个用户量级下
> 一年也就几个 GB，最低配服务器完全够。磁盘剩余低于 500MB 时上传会自动拒绝，
> 不会把数据库一起拖下水。

## 9. 什么时候该升级

SQLite 单机跑到几百个并发用户没问题，冷启动阶段完全够。
真到了扛不住的那天（写入变慢、出现 database is locked），
把 `DATABASE_URL` 换成 MySQL/Postgres 的连接串就行 ——
后端用的是 SQLAlchemy ORM，代码一行不用改。

同样按计划书的原则：**每一分钱都等真的有人用了再花。**
