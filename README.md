# XX转运Pro

日本转运小程序 MVP：用户把包裹寄到我们的日本仓地址，在小程序里预报包裹、下单发货、跟踪物流。

详细背景、竞品解包出的完整接口清单、差异化设计见 [`docs/plan.md`](docs/plan.md)。

## 目录结构

```
backend/       FastAPI + SQLite 后端，方法名路由 (POST /api {method, params, token})
miniprogram/   微信小程序原生前端，10 个页面覆盖 MVP 全流程
docs/plan.md   项目计划书 + 竞品接口清单
```

## 快速开始

### 1. 启动后端

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export STAFF_KEY=随便设一个字符串   # 仓库/客服操作用，见下面第 2 步
export SERVICE_WECHAT=你的微信号     # 订单页让用户加这个微信转账付款
uvicorn app.main:app --reload --host 0.0.0.0 --port 8811
```

详见 [`backend/README.md`](backend/README.md)。

### 2. 不装微信开发者工具，先确认后端本身是通的

另开一个终端跑一键冒烟测试，把"登录→建地址→预报→仓库入库→下单→仓库发货→
追加物流轨迹→客户查详情"这条主线全走一遍，任何一步出错会直接报错退出：

```bash
cd backend
STAFF_KEY=你在第1步设置的那个值 python3 scripts/smoke_test.py
```

看到最后一行 `[PASS] 全流程走通了` 就说明后端没问题。

小程序页面里的交互逻辑（选地址/线路、省市区选择、切 tab 等）也可以不开微信开发者工具先测一遍，
需要本机装有 Node 18+，后端保持运行：

```bash
node backend/scripts/page_test/test_pages.js
```

仓库/客服那几个操作（标记入库、标记发货、追加轨迹）现在也有一个网页可以点，不用背
接口参数：浏览器打开 `http://127.0.0.1:8811/admin/`，填入 `STAFF_KEY` 保存，
就能看到"待入库包裹 / 待发货订单 / 运输中订单"三个 tab 直接操作。

### 3. 打开小程序

用微信开发者工具「导入项目」选择 `miniprogram/` 目录（AppID 可选"测试号"）。
`miniprogram/utils/config.js` 里的 `BASE_URL` 默认指向 `http://127.0.0.1:8811`，
本地联调记得在开发者工具里关闭"域名校验"（详情 -> 本地设置 -> 不校验合法域名）。

登录页提供了两种方式：
- **微信一键登录**：需要后端配置了 `WX_APPID`/`WX_SECRET`（见 backend/README.md）
- **本地联调登录**：不需要任何微信凭证，随便填个用户名即可，方便先把全流程跑通

#### 用手机真机测试

手机访问不到电脑上的 `127.0.0.1`，需要：

1. 手机和电脑连同一个 Wi-Fi，查出电脑的局域网 IP（Windows `ipconfig`，macOS `ipconfig getifaddr en0`，
   形如 `192.168.1.23`）
2. 把 `miniprogram/utils/config.js` 的 `BASE_URL` 改成 `http://192.168.1.23:8811`（换成你的 IP）。
   后端启动命令里的 `--host 0.0.0.0` 不能省，否则只接受本机访问
3. 先用手机浏览器打开 `http://192.168.1.23:8811/health`，能看到 `{"ok":true}` 再继续；打不开
   一般是电脑防火墙拦了 8811 端口
4. 开发者工具点「预览」或「真机调试」扫码。真机上要在小程序右上角「···」→「开发调试」→
   「打开调试」，然后重新进入小程序，否则 http 地址会被域名校验拦掉
5. 测完记得把 `BASE_URL` 改回来，别提交局域网 IP

### 4. 在小程序里走一遍 MVP 全流程

1. 登录 →「我的」里填昵称和手机号（仓库靠它认出包裹是谁的）→ 首页复制日本仓地址和会员代码，
   看「国际物流费用说明」
2. 预报包裹：只填快递单号，选一下包裹现在的状态（卖家未发货 / 在路上 / 显示已签收）
3. 后台 `http://127.0.0.1:8811/admin/`「包裹入库」：填实际称重，点「标记入库」
   （没预报的包裹用上面的表单，按包裹上写的会员代码登记）
4. 小程序「去下单」：选包裹、地址（没有就新增，身份证号必填）、线路（精致小 / 无忧草）→ 提交
5. 订单状态变成「待付款」，订单详情里显示金额和客服微信 → 用户加微信转账
6. 后台「待发货订单」点「确认收款」→ 选快递公司、填国际转运单号，点「标记发货」
7. 小程序订单详情能看到国际转运单号、航班日期和物流轨迹；后台「运输中订单」可以手动追加轨迹
8. 用户在订单详情点「确认收货」（或后台点「标记签收」）→ 订单进入「已签收」

也可以先下单、后入库（包裹还在路上就提交订单）：订单会显示「待入库称重」，运费先按预报重量估算，
全部包裹入库称重后变成「待付款」。

计费规则（首重/续重、价值上限、囤货费、同一航次身份证/地址/电话不能重复）见 `backend/README.md`。

## MVP 范围

已实现：微信登录（+ 本地联调登录）、会员信息（昵称/手机号/会员代码）、收件地址（含全国省市区
三级联动、实名信息）、日本仓地址、包裹预报（只需单号，可粘贴快递单文字自动识别）、仓库称重入库、
我的包裹、运费计算器、国际物流费用说明、下单、线下收款确认、发货（航次查重）、订单列表/详情、
物流轨迹（可接快递100 自动拉取）、确认收货、微信订阅消息通知（入库/发货/签收）、公告。

按计划书第 2 节先砍掉：余额充值/提现、拼团砍价、多店铺切换、会员等级体系、短信验证码
（`System.Config.getVertification` 占位待接入第三方短信网关）。

## 关于竞品 .wxapkg

竞品小程序包是加密的（`V1MMWX` 头，微信开发者工具的标准加密格式），解密需要该小程序的
`wxid` 作为密钥材料，这次没有再重复解包。不过 `docs/plan.md` 第 7 节的接口清单就是此前
已完成的解包结果整理，本仓库后端就是照着这份清单实现的。
